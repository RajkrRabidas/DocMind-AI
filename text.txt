WEEK 3 — RAG system build

Ye project ka heart hai.

Day 15 — Chunking samjho aur implement karo

PDF ka pura text AI ko direct nahi dena.

Kya karna hai:
text ko small chunks me todna hai
har chunk ka size around 500–1000 characters ya tokens
overlap add karo
Example:

Chunk 1 = line 1–20
Chunk 2 = line 18–38

Ye overlap isliye hota hai taki context na tute.

Backend me utility banao:

chunkText(text)

Aaj ka end result:

Extracted text chunks me convert ho.

Day 16 — Embeddings generate karo
Kya karna hai:
har chunk ko embeddings me convert karo
embeddings matlab number vectors
ye vector semantic meaning carry karta hai
Input:

chunk text

Output:

vector

Aaj ka end result:

Ek document ke chunks ke embeddings generate ho jaye.

Day 17 — Vector DB store
Kya karna hai:
embeddings ko vector DB me save karo
metadata ke saath save karo
Metadata example:
userId
documentId

title
Important:

Har chunk store karte waqt metadata zarur save karo.

Aaj ka end result:

Document searchable ho jaye vector DB me.

Day 18 — Query to embedding
Kya karna hai:

Jab user question puche:

us question ko bhi embedding me convert karo

Example:
“budget kaha mention hua hai?”

Ye query embedding vector DB me search karega.

Aaj ka end result:

Question embedding ready ho.

Day 19 — Similarity search
Kya karna hai:
top 3 ya top 5 relevant chunks laao
vector similarity search use karo
Result:

Question ke closest chunks milenge

Example:

User asked: “Main conclusion kya hai?”
System returns:

chunk 7
chunk 11
chunk 14
Aaj ka end result:

Relevant chunks successfully retrieve ho.

Day 20 — Final RAG answer generation

Ab final step:

Flow:
user question
query embedding
top chunks retrieve
prompt build karo
AI ko bolo:
“sirf provided context ke basis par answer do”
Prompt structure:
system instruction
retrieved chunks
user question
Rule:

AI ko bolo hallucinate mat kare.
Agar answer context me nahi hai, bolo “document me ye info nahi mili”.

Aaj ka end result:

User document se question puch ke answer le sake.
